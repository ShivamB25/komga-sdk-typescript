Metadata lookup operations in the Komga 1.26.3 schema return paginated `PageString`, `PageInteger`, or `PageAuthorDto` data. Query parameters are flat generated parameters, and the client is passed in the second options object when parameters are present.

<Note>
The generated v2 operations below are the supported referential API. Regeneration keeps deprecated v1 operations as compatibility exports when names collide (for example, `getGenres1`); do not import those suffixed legacy functions.
</Note>

## Genres

```typescript
import { getGenres } from 'komga-sdk';

const result = await getGenres(undefined, { client });
if (!result.error) {
  for (const genre of result.data?.content ?? []) console.log(genre);
}
```

Filter by library or collection with the generated `library_id` and `collection_id` keys:

```typescript
const libraryGenres = await getGenres(
  { library_id: ['library-123'] },
  { client },
);
const collectionGenres = await getGenres(
  { collection_id: ['collection-123'] },
  { client },
);
```

### Filter-key reference

Use the generated names exactly as shown below. The underscore names mirror the wire query keys, and every scope identifier is an array in the v2 signatures:

| Operation(s) | Library | Collection | Other scope |
| --- | --- | --- | --- |
| `getAgeRatings`, `getGenres`, `getLanguages`, `getPublishers`, `getSeriesReleaseYears`, `getSharingLabels` | `library_id?: string[]` | `collection_id?: string[]` | — |
| `getTags` | `library_id?: string[]` | `collection_id?: string[]` | `series_id?: string[]`, `readlist_id?: string[]` |
| `getAuthors`, `getAuthorsNames`, `getAuthorsRoles` | `library_id?: string[]` | `collection_id?: string[]` | `series_id?: string[]`, `readlist_id?: string[]` |

All of these operations also accept `unpaged`, `page`, and `size`; operations that search string values additionally accept `search`, and author operations expose `role` where generated. They return a page, so read values from `result.data?.content ?? []`. Do not translate these names to camelCase (`libraryId` or `collectionId`)—those keys are not part of the generated signatures.

## Tags

The tag endpoints use the same flat filter style, with endpoint-specific keys:

```typescript
import { getTags } from 'komga-sdk';

const [allTags, bookTags, seriesTags] = await Promise.all([
  getTags(
    { library_id: ['library-123'], include: 'BOTH', unpaged: true },
    { client },
  ),
  getTags(
    { library_id: ['library-123'], include: 'BOOK', unpaged: true },
    { client },
  ),
  getTags(
    { library_id: ['library-123'], include: 'SERIES', unpaged: true },
    { client },
  ),
]);

console.log({
  all: allTags.data?.content ?? [],
  books: bookTags.data?.content ?? [],
  series: seriesTags.data?.content ?? [],
});
```

`getTags` replaces the deprecated v1 tag routes. Its `include` query value selects `SERIES`, `BOOK`, or `BOTH`; scope IDs (`library_id`, `collection_id`, `series_id`, and `readlist_id`) are arrays. Use the same operation for book-only and series-only lookups rather than importing regenerated legacy functions.

## Authors

List authors with optional search, role, scope, and pagination parameters:

```typescript
import { getAuthors } from 'komga-sdk';

const result = await getAuthors(
  {
    search: 'Toriyama',
    role: 'writer',
    library_id: ['library-123'],
    page: 0,
    size: 50,
  },
  { client },
);

if (!result.error) {
  for (const author of result.data?.content ?? []) {
    console.log(`${author.name} (${author.role})`);
  }
}
```

For autocomplete, use `getAuthorsNames({ search }, { client })`; it returns a paginated `PageString`:

```typescript
import { getAuthorsNames, getAuthorsRoles } from 'komga-sdk';

const names = await getAuthorsNames({ search: 'Tor' }, { client });
const roles = await getAuthorsRoles(undefined, { client });
console.log(names.data?.content ?? [], roles.data?.content ?? []);
```

## Publishers, languages, ratings, sharing labels, and release years

These endpoints return paginated values. `getPublishers`, `getLanguages`, `getAgeRatings`, `getSharingLabels`, and `getSeriesReleaseYears` accept `library_id?: string[]` and `collection_id?: string[]`:

```typescript
import {
  getPublishers,
  getLanguages,
  getAgeRatings,
  getSharingLabels,
  getSeriesReleaseYears,
} from 'komga-sdk';

const filters = { library_id: ['library-123'] };
const [publishers, languages, ratings, labels, releaseYears] = await Promise.all([
  getPublishers(filters, { client }),
  getLanguages(filters, { client }),
  getAgeRatings(filters, { client }),
  getSharingLabels(filters, { client }),
  getSeriesReleaseYears(filters, { client }),
]);

console.log({
  publishers: publishers.data?.content ?? [],
  languages: languages.data?.content ?? [],
  ratings: ratings.data?.content ?? [],
  labels: labels.data?.content ?? [],
  releaseYears: releaseYears.data?.content ?? [],
});
```

Languages use ISO 639-1 codes such as `en`, `ja`, and `fr`. Use `getSeriesReleaseYears` for year values; it replaces the deprecated release-date referential route.

## Build filter options

Fetch independent lists in parallel and keep each generated result separate so errors remain attributable:

```typescript
import {
  getGenres,
  getTags,
  getPublishers,
  getLanguages,
  getAgeRatings,
  getAuthorsRoles,
} from 'komga-sdk';

async function getFilterOptions(libraryId?: string) {
  const filters = libraryId ? { library_id: [libraryId] } : undefined;
  const [genres, tags, publishers, languages, ageRatings, authorRoles] =
    await Promise.all([
      getGenres(filters, { client }),
      getTags(filters, { client }),
      getPublishers(filters, { client }),
      getLanguages(filters, { client }),
      getAgeRatings(filters, { client }),
      getAuthorsRoles(filters, { client }),
    ]);

  return {
    genres: genres.data?.content ?? [],
    tags: tags.data?.content ?? [],
    publishers: publishers.data?.content ?? [],
    languages: languages.data?.content ?? [],
    ageRatings: ageRatings.data?.content ?? [],
    authorRoles: authorRoles.data?.content ?? [],
  };
}
```

## Autocomplete and library summaries

For an autocomplete field, query `getAuthorsNames` rather than loading a full author page. Debounce keystrokes in the UI and avoid sending empty searches:

```typescript
import { getAuthorsNames } from 'komga-sdk';

async function searchAuthors(search: string): Promise<string[]> {
  if (search.trim().length < 2) return [];
  const result = await getAuthorsNames({ search }, { client });
  return result.error ? [] : result.data?.content ?? [];
}
```

You can also build a lightweight metadata summary for an administration view. Use `unpaged: true` when each value list must be complete; authors remain paginated, so use `totalElements` rather than `content.length` for the count:

```typescript
import {
  getAuthors,
  getGenres,
  getPublishers,
  getTags,
} from 'komga-sdk';

async function getLibrarySummary(libraryId: string) {
  const filters = { library_id: [libraryId], unpaged: true };
  const [genres, tags, publishers, authors] = await Promise.all([
    getGenres(filters, { client }),
    getTags(filters, { client }),
    getPublishers(filters, { client }),
    getAuthors({ library_id: [libraryId], page: 0, size: 1 }, { client }),
  ]);

  return {
    genreCount: genres.data?.content?.length ?? 0,
    tagCount: tags.data?.content?.length ?? 0,
    publisherCount: publishers.data?.content?.length ?? 0,
    authorCount: authors.data?.totalElements ?? 0,
  };
}
```

If one request fails, inspect that result's `error` and `response` instead of silently treating every list as empty. Parallel requests improve latency, but they do not make a partial response a successful metadata snapshot.


## Error handling

The default result exposes typed generated errors and the native response. Use the status for transport-level decisions:

```typescript
import { getGenres, KomgaApiError, unwrap } from 'komga-sdk';

const result = await getGenres(undefined, { client });
if (result.error) {
  console.error(`Metadata request failed (${result.response?.status})`, result.error);
}

try {
  const genres = unwrap(await getGenres(undefined, { client }));
  console.log(genres.content ?? []);
} catch (error) {
  if (error instanceof KomgaApiError) {
    console.error(error.status, error.body);
  } else {
    throw error;
  }
}
```
