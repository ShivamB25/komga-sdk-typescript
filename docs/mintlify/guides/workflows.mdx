Generated operations compose directly. Each call takes a flat parameter object when needed and `{ client }` in the second argument. Calls return a result union unless you use `unwrap`.

## Find and update matching series

Use `getSeries` with a `seriesSearch` document, then send a flat `seriesMetadataUpdateDto` to `updateSeriesMetadata`:

```typescript
import { getSeries, updateSeriesMetadata } from 'komga-sdk';

const listed = await getSeries(
  {
    page: 0,
    size: 50,
    seriesSearch: { fullTextSearch: 'classic' },
  },
  { client },
);

if (listed.error) throw listed.error;

for (const series of listed.data?.content ?? []) {
  const updated = await updateSeriesMetadata(
    {
      seriesId: series.id,
      seriesMetadataUpdateDto: {
        summary: 'Curated collection',
      },
    },
    { client },
  );
  if (updated.error) console.error(series.id, updated.error);
}
```

`updateSeriesMetadata` succeeds with HTTP 204 and has no response payload. Do not read `updated.data` as a series.

## Find and update matching books

The same pattern works for books. `bookSearch` is the request body while pagination remains flat; `updateBookMetadata` returns `204`, so collect the IDs you changed rather than expecting updated book objects:

```typescript
import { getBooks, updateBookMetadata } from 'komga-sdk';

const listed = await getBooks(
  {
    page: 0,
    size: 50,
    sort: ['metadata.title,asc'],
    bookSearch: { fullTextSearch: 'classic' },
  },
  { client },
);
if (listed.error) throw listed.error;

const updatedIds: string[] = [];
for (const book of listed.data?.content ?? []) {
  const updated = await updateBookMetadata(
    {
      bookId: book.id,
      bookMetadataUpdateDto: { summary: 'Curated collection' },
    },
    { client },
  );
  if (updated.error) {
    console.error(`Could not update ${book.id}`, updated.error);
  } else {
    updatedIds.push(book.id);
  }
}
console.log(`Updated ${updatedIds.length} books`);
```


## Scan a library and list recent books

List libraries, submit a scan, then list books with flat pagination and sorting:

```typescript
import { getLibraries, libraryScan, getBooks } from 'komga-sdk';

const libraries = await getLibraries({ client });
const library = libraries.data?.[0];
if (!library) throw new Error('No accessible library');

const scan = await libraryScan(
  { libraryId: library.id, deep: false },
  { client },
);
if (scan.error) throw scan.error;
// A scan is accepted asynchronously (HTTP 202); it has no useful data payload.

const books = await getBooks(
  {
    page: 0,
    size: 20,
    sort: ['metadata.releaseDate,desc'],
    bookSearch: {},
  },
  { client },
);
console.log(books.data?.content.map((book) => book.metadata.title) ?? []);
```

Because a scan is accepted asynchronously, the immediately following list can still show the pre-scan state. Treat the list as a snapshot, and refresh it after your own task-completion signal or a deliberate delay; there is no generated task-progress operation in this SDK.


## Build thumbnail URLs for a UI

Image getters return `Blob | File`, not a URL string. Create object URLs in the application and revoke them when the image leaves the UI:

```typescript
import { getBookThumbnail } from 'komga-sdk';

async function loadThumbnail(bookId: string): Promise<string | undefined> {
  const result = await getBookThumbnail({ bookId }, { client });
  if (result.error || !result.data) return undefined;
  return URL.createObjectURL(result.data);
}

const thumbnailUrl = await loadThumbnail('book-123');
if (thumbnailUrl) console.log(thumbnailUrl);
```

## Handle errors at the boundary

Keep non-throwing generated results at lower-level workflow steps, or use `unwrap` at a boundary where the workflow should fail:

```typescript
import { getLibraries, KomgaApiError, unwrap } from 'komga-sdk';

try {
  const libraries = unwrap(await getLibraries({ client }));
  console.log(libraries);
} catch (error) {
  if (error instanceof KomgaApiError) {
    console.error(error.status, error.body);
  } else {
    throw error;
  }
}
```
